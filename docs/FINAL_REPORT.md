# Rally MVP implementation report

The repository now contains a working fictional preview plus a Supabase/Stripe-oriented backend implementation. Core ranking and financial invariants were executed in PostgreSQL tests. This is **not a verified live-money production launch**: external configuration and integration validation remain outstanding.

| Requested area               | Result                                                                                                                                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Architecture                 | Modular Vinext/React/TypeScript application; PostgreSQL domain functions; HTTP Supabase clients; provider adapter boundary                                                                                               |
| Implemented features         | Sponsored geographic leaderboards, search, account profiles, estimates, boost dialog, share links/PNG cards, add-listing flow, Auth/claims/report endpoints, dashboard and administration                                |
| Routes                       | Public discovery/account/policy routes and protected management/payment APIs; complete inventory in README                                                                                                               |
| Database tables              | 18 normalized tables for listings, hierarchy, ownership, purchases, immutable ledger/events, private operations and analytics                                                                                            |
| Database migrations          | `20260905072810_initial_rally.sql`; production reference seed and separately labeled development-only financial/profile seed                                                                                             |
| Location system              | Optional hierarchy levels; ancestor/descendant queries; cycle guard; declared/verified/disputed trust states; UAE/GCC reference data                                                                                     |
| Ranking algorithm            | Verified cumulative cents descending; first verified promotion ascending; stable UUID fallback; no authoritative stored rank                                                                                             |
| Promotion system             | Guest or authenticated payer; minimum 100 USD cents; configurable maximum; pending checkout; transactional verified credit                                                                                               |
| Payment provider abstraction | Checkout, signed verification, retrieval, refund interface; Stripe-specific details isolated                                                                                                                             |
| Active payment provider      | Disabled in preview; Stripe **test-mode** adapter implemented, not connected or end-to-end tested                                                                                                                        |
| Webhook security             | Raw-body signature verification; timestamp tolerance; expected amount/currency/payment binding; service-only transactional idempotency                                                                                   |
| Refund/dispute handling      | Immutable negative adjustments; partial/full refunds; dispute removes remaining purchase value; stale-success protection; won-dispute recredit not implemented                                                           |
| Auth                         | Supabase email magic links, fixed-origin PKCE callback, fresh identity checks and cookie-refresh proxy; hosted delivery/session testing required                                                                         |
| Account claims               | Private evidence, separate ownership table, manual administrator decisions; promotion never grants ownership                                                                                                             |
| Admin                        | Database membership and server auth required; audited approval, rejection, suspension, claim decisions, location correction and report resolution                                                                        |
| Moderation                   | Pending listing default; reports and claims queues; basic operational screen                                                                                                                                             |
| Analytics                    | First-party funnel events; verified conversion recorded transactionally; signed-in repeat-promotion analysis supported; guest long-term attribution incomplete                                                           |
| Security                     | Integer amounts, strict request validation, same-origin mutations, shared limits, trusted redirects, no client secrets or card storage                                                                                   |
| RLS                          | All tables protected; browser roles explicitly denied ranking/ledger writes and privileged RPCs; per-user private record isolation tested                                                                                |
| Test results                 | 20 domain/database tests passed; 17 page/API smoke checks passed                                                                                                                                                         |
| Typecheck                    | Passed                                                                                                                                                                                                                   |
| Lint                         | Passed for authored code; vendored starter code excluded and documented                                                                                                                                                  |
| Build status                 | Production Worker/client build passed                                                                                                                                                                                    |
